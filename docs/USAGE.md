# 邻传 0.6.0 使用说明

两台电脑把便携包完整解压到可写目录，然后各自双击 `邻传.exe`。不用安装 Python，不用浏览器，两端都能主动聊天和发送文件。

1. 接入同一个可信局域网，等待左侧显示运行邻传的设备。
2. 选择对方，直接输入文字并发送；无需开始或结束聊天。
3. **首次连接才需确认设备：** 双方通过当面或电话核对验证码，一致后点击“一致，记住设备”。首次待发消息/文件在确认后继续发送。以后重开 App 也不重复确认。
4. Enter 发送文字，Shift+Enter 换行。聊天输入框紧接聊天显示区下方，文件操作位于输入区下面。
5. 发文件：选择文件 → 发送文件；或选设备后直接拖入窗口。发送方不用再确认，接收方点击“接收”或“拒绝”；接收后也能点击“停止接收”。确认前不传输文件内容；取消会清除正在接收的临时文件，已完整保存的文件保留。
6. 接收完成点顶部“接收文件夹”。支持同时聊天和传文件，双向操作相同。

窗口默认 720×580，可以缩小至 640×520 或自行放大。设置中更改设备名、选择网卡。

**范围和保存：** 单条文字最多 4 KiB，单文件最多 2 GiB，每批最多 50 个文件、合计 20 GiB；暂不支持文件夹，请先压缩。文件保存于 EXE 旁 `邻传数据/received`，保持原文件名，不添加随机字段。同名时由接收方选择覆盖、另存或取消；同一批里的重名文件需另选名称。覆盖只在文件完整接收且校验通过后进行，取消或校验失败保留原文件。聊天仅保留在内存中，关闭 App 后清空，最多缓存最近 300 条显示记录/设备；不支持离线消息、自动重发、断点续传。内部连接最长 1 小时，到期后下一次发送会自动连接；关闭或离线不需要手动结束聊天。

**网络：** 只接受私有 IPv4/本机地址，发现用 UDP 45876，通信用 TCP 8765，HTTPS 点对点，不使用公网中继或代理，不发送遥测。接收授权与证书 pin 防止其他设备随意访问文件。首次验证码必须通过可信渠道核对，设备显示的名字不等于可信身份。设备 ID、证书/私钥与已确认的证书指纹保存在本地“邻传数据”，不上传 GitHub；升级和重启保留此目录。发现其他设备不会自动信任。身份文件缺损或已记住设备的证书变化时阻止连接，不静默重新信任。

**防火墙：** 提示时只允许专用网络；公共网络权限不需要。程序不会自动更改防火墙。路由器访客网络/客户端隔离、企业网络、VPN 多网卡或禁止组播时可能无法发现。可在设置选正确 IPv4，再用“手动连接”填对方地址和端口。新交互要求两端均使用 0.5.0 或更新版本；对方没有自动聊天能力时会提示升级。

**拖拽没有反应：** 两端程序都以普通用户运行；从资源管理器拖入真实文件，别拖文件夹、ZIP 内虚拟条目或云端未落地文件。Windows 权限级别不同可能阻止拖拽。

**验证范围：** 本机真实 HTTPS 双向收发、组播发现、Tk 窗口及打包自检已验证。不同物理电脑、不同路由器和防火墙配置仍需实际验证。

## 更新软件

设置 → 软件更新 · GitHub → 检查更新 → 下载新版 ZIP → 安装并重启。下载及安装前均校验 SHA-256；更新助手等旧程序退出，自动替换 EXE 并重新打开，不用手动覆盖。安装前请完成或取消文件传输。聊天记录只在内存中，重启会清空。

更新保留原 `邻传数据` 目录、接收文件、设备名、私钥和已确认设备；只替换当前 EXE。目录需可写，不需要管理员权限。旧 EXE 备份与结果保存在 EXE 旁 `.lindrop-update-*/previous.exe` 与 `result.json`。替换或启动进程失败时回退旧版；若新版成功启动后自身出现问题，可退出程序后用该备份恢复。备份和下载 ZIP 可在确认新版正常后删除。

发布包固定叫 `lindrop-windows-x64.zip`，不要每次放进新的版本目录。防火墙规则按 EXE 完整路径记录，新版在原路径更新，首次授权后通常可沿用规则；规则被清理、权限不足或网络类别改变仍可能需要处理。程序不修改防火墙或网络类别，启动时先显示主窗口，识别到 Windows 中英文网络授权窗口关闭后尝试恢复主窗口（不保持置顶）。

0.5.0 或更早版本没有安装助手且只识别带版本名的旧包，请直接打开 GitHub Releases 下载固定名 ZIP；首次升级到 0.6.0 仍需退出程序、解压新包、覆盖 EXE 一次，保留数据目录；之后使用上述安装按钮。源码运行请通过 Git 更新。

只有主动检查或下载软件更新时才访问 GitHub；不后台检查，不上传聊天或文件。仅点击“安装并重启”才执行已校验更新。GitHub 连接失败不影响局域网功能。

公开仓库：[powersqb/lindrop](https://github.com/powersqb/lindrop)，正式版下载在 [Releases](https://github.com/powersqb/lindrop/releases)。SHA-256 通过校验表示附件与 GitHub 发布记录一致，不等同 Windows 数字签名。

## 设备重装或证书变化

确认确实是对方重装/重新创建数据目录后，选择该设备 → 设置 → 设备身份 / 忘记设备 → 忘记此设备，再发送并重新核对首次验证码。操作前先完成或取消文件传输。若对方完全重新建立了设备 ID，它会显示为未确认的新设备，仍需首次核对。

不要把“邻传数据”复制给另一台电脑：这会复制私钥和设备身份。另一台电脑只复制发布包，让它创建自己的数据目录。证书按指纹验证，不使用公共 CA；旧版保留的自签证书同样按指纹识别，日期不触发自动换证。证书丢失时恢复自己的备份，或明确重建身份后重新核对。

## 安卓手机广播地址异常

若手机手动连接电脑后能聊天，但电脑发手机提示证书变化，请升级电脑邻传至 0.6.1。更新重启后，在手机先发送一条文字，再从电脑发文件；电脑会使用聊天中经反向 TLS 验证的手机地址，每次文件连接仍严格校验原证书。不要因这一提示直接删除设备信任。
